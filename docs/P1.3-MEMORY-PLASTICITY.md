# P1.3 · 记忆巩固与可塑性

> 状态：实现与自动化验证完成，待部署后的真实 QQ 观察。范围仅限会话状态恢复、owner 手动整理和 facts 冲突降权；不改 `docs/CONTRACT.md`、qq-gateway、配置默认值或运行时依赖。

## 1. 为什么需要 P1.3

P1.2 已把自动整理阈值调到当前小规模对话可达的范围，但线上仍有两个问题：

1. 进程重启后只恢复摘要，最近 history、整理计数和 `lastTurnAt` 都从头开始，自动整理可能重新等满 30 分钟和 6 轮，甚至丢失触发状态。
2. facts 只有“再次提及 → 复习强化”，没有“新事实强冲突 → 旧事实降权”；这与 ADR-D5 的可塑性目标不一致。
3. owner 没有办法在不改配置、不重启的情况下立即触发一次整理。

## 2. 会话状态恢复

`state/sessions/<sanitized-sessionKey>.json` 在原有 `summary` / `lastActiveAt` 之外新增可选字段：

```json
{
  "sessionKey": "qq:private:10001",
  "summary": "最近对话摘要",
  "lastActiveAt": "2026-11-07T00:00:00.000Z",
  "history": [
    { "role": "user", "content": "进入过模型的原文" },
    { "role": "assistant", "content": "实际送达的回复" }
  ],
  "turnsSinceCompaction": 3,
  "lastTurnAt": "2026-11-07T00:00:00.000Z"
}
```

规则：

- 只持久化真正进入过模型的 user/assistant 原文，最多 `historyTurns × 2` 条；`modelEligible=false` 的群消息不会通过 state 恢复进模型。
- 旧 JSON 缺少新字段时按原行为读取；非法 history 项读取时忽略。
- 每轮 `runTurn` 结束和 `commitAssistant` 成功后原子写回；普通状态写失败只告警一次，不阻断聊天。
- 压缩流程仍要求摘要写盘成功后才截断历史；该步骤失败继续放弃本次压缩。
- 重启后恢复 history、整理计数和最近轮次时间，下一次满足 `idleMs + minTurns` 边界即可继续整理。

## 3. owner 手动整理

新增 owner-only `!整理`：

- CLI 和 QQ 都支持；QQ 仍只在单条 owner 批次、模型调用前执行。
- 无参数；带参数返回用法。
- 命令前缀 `!` 兼容全角 `！`，避免中文输入法下被当成普通聊天。
- 绕过 `idleMs` / `thresholdTokens` / `minTurns`，但仍要求有非空 history 和记忆层。
- 与自动整理共用同一个内部 `runCompaction` 路径，成功顺序不变：整理轮 → facts/selfNote 写盘 → 摘要与状态持久化 → 截断历史。
- 命令回复不写 assistant L0/history，不回显模型整理 JSON，只返回事实/自认知条数和摘要状态。

## 4. 可塑性规则

强冲突只在写盘时判断，条件全部满足才生效：

1. 同一 `sessionKey`、同一 `tag`、旧事实未归档；
2. 新旧文本不完全相同（同文本仍走复习）；
3. 先按标点和“但/不过/而且/而不/而非”等转折词分句；
4. 每句归一化为“内容主体”：去掉语气词、时态/转折词、否定噪声和情感谓语（喜欢/讨厌/爱/恨），保留主语与“猫/北京/吃辣”等具体内容；仅容忍主语省略差异，不同显式主语不交叉判定；
5. 只有两个分句的主体完全一致时才比较极性。三态边界：
   - `conflict`：同一主体存在相反极性，且没有同极性确认 → 旧事实降权；
   - `uncertain`：有否定或负面情感，但主体不明确、主体不同、主客倒置，或双重/叠加否定（含 `未/从未/并未`）中性 → 不降权、不复习；
   - `no-conflict`：同主体同极性，或没有极性冲突 → 允许正常复习。

命中后旧事实追加一条修订：

- `baseWeight *= 0.5`
- 写入 `conflictedAt`
- 保留原文、`reviews`、`lastReviewAt`、`createdAt`
- 不删除；是否归档仍由原权重衰减线决定

每条旧事实最多降权一次，避免连续改写造成指数级衰减。`autoReview` 对强冲突消息跳过强化，避免“否定旧事实”反而延长旧事实半衰期。普通再提及只有在“同主体、同 core”或“新消息在旧事实对象后以并列连接词追加了实际内容”时才执行 `reviews+1` 并提升注入排序；不同显式主体、不同对象、主客倒置和反向删减不复习。该约束优先防止错误强化，接受少量口语变体漏复习。

分句和主体判断避免把“我喜欢猫，但不喜欢狗”里的整体否定误套到“猫”上，也避免“他不在北京但喜欢猫”因无关分句而误降权。多分句省略主语按前序显式主语继承（“他不在北京但喜欢猫”里的“喜欢猫”属于“他”），避免与“她/我喜欢猫”跨主体误配。相反，“我喜欢狗，不喜欢猫”里的“不喜欢猫”仍能命中旧事实“喜欢猫”；“他吃火锅但不吃辣”仍能命中“吃辣”。

v1 使用确定性规则，不调用 LLM 判定语义冲突；宁可漏判，不为了覆盖率误伤无关事实。

## 7. 残余风险

- 冲突规则是规则级保守实现，无法识别所有同义改写、反义词和跨句冲突；漏判时旧事实仍会自然衰减，不会造成数据丢失。
- 分句/主体归一化能抑制常见混合否定误判，但仍不是语法解析器；极长复句、主语省略（含非代词主语）或主体表述差异仍需真实语料观察。
- 每条旧事实只降权一次；如果后续真实语义再次反转，应由更新的新事实在注入排序中胜出，而不是继续压低旧事实。
- `autoReview` 仍是确定性规则，不是语义解析器：同义改写、部分口语强调（如“他挺喜欢猫”）和少数量词/并列换序可能漏复习；这是为避免误强化而接受的保守取舍。不同显式主体/对象已被阻断。
- CLI `!整理` 已把 `activeAbort` 贯穿到整理轮；Ctrl+C 会立即中止，不写 facts/selfNote、不截断 history，也不进入压缩失败防抖。真实 TTY 的中断体验仍待人工黑盒确认。
- 压缩非事务：摘要写失败时 facts/selfNote 可能已写入；本轮保持既有顺序，不回滚、不截断历史。
- 本轮只做自动化验证，未启动真实 QQ/SnowLuma 链路；`!整理` 的真机回执需部署后观察。
- 进程在“已生成回复但尚未发送收尾”之间崩溃时，会话状态可能保留 user 而没有 assistant；这与 L0/Receipt 的既有恢复语义一致，未在本轮引入新的跨进程事务。
