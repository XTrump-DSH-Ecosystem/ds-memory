# P3-2 · Hybrid 检索设计

> 状态：**评测设计，非生产实现**。不修改 `src/`、不新增依赖、不改变 `Retriever` 公共接口。
> 日期：2026-11-05
> 上游：`docs/P3-1-REPORT-A.md`、`docs/P3-EVAL.md` §7。

## 1. 要解决的问题

P3-1 的结论不是“embedding 不够召回”，而是“embedding 不会弃权”：

- embedding 在修正后的保留集上 Recall@5 已达 1.000，但负例正确率只有 0.200。
- 单独调全局余弦阈值会把正例和负例一起砍掉；阈值不是可靠的弃权判据。
- bigram 对精确名词、数字、英文标识符强，但换说法会漏召回。

因此 P3-2 采用职责分离：

1. **语义模型负责“可能相关”**；
2. **词面证据负责“是否值得回答”**；
3. **精确标识符负责最高优先级**。

弃权不依赖一个全局相似度阈值，避免用测试集负例反向拟合阈值。

## 2. 数据流

```text
L0 记录
  → sessionKey / modelEligible 过滤（与 BigramRetriever 同规则）
  → 候选并集：bigram top 20 + cosine top 20
  → 证据门：硬标识符 / 词面锚点 / 跨文档分裂检查
  → 融合排序：0.25 × 归一化 bigram + 0.75 × 归一化 cosine
  → 精确标识符加成
  → 近因、ID 兜底排序
  → 前 80 字去重，取 top 5
```

隔离发生在候选生成之前，不在排序之后补救；跨 session 或 `modelEligible=false` 的记录不进入候选集。

## 3. 证据门

### 3.1 硬标识符

查询中的数字/英文连续段（长度至少 2）视为硬锚点。任意同 session 的候选文本包含同一 token 时，直接通过证据门，并获得排序加成。

用途：`4090`、`8848`、`green-lantern-77`、`4K` 这类标识符不应被语义分数淹没。

### 3.2 词面锚点

从查询提取中文 bigram，过滤纯功能字组合；另外用一组**评测专用**的最小同义/别名组做查询扩展。每个锚点或别名组是一个“证据槽”。

通过规则：

- 没有任何槽被任何同 session 记录命中 → 弃权；
- 有 2 个以上槽被命中，但所有命中分散在不同记录、没有任何单条记录同时覆盖 2 个槽 → 弃权（`split-evidence`）；
- 其余情况通过。

`split-evidence` 的作用是拒绝“公司邮箱密码”这类查询：一条记录只有“邮箱”，另一条只有“密码”，没有任何一条同时支持完整事实。它不是相似度阈值，不会因为模型分数高就放行。

### 3.3 别名组的边界

别名组位于 `tests/eval/hybrid-aliases.json`，当前只用于评测，不是生产配置。它覆盖 `GPU/显卡/图形卡`、`电脑/笔记本`、`屏幕/显示器`、语言、宠物、价格、名字、讨厌/不喜欢、后台/管理员、分辨率等最小集合。

生产化前必须重新评审：

- 别名是否会引入错误合并（尤其是价格、名字这类单字扩展）；
- 是否改为可审计的配置而非代码常量；
- 新词是否需要用户可见的增删机制；
- 别名扩展只能影响证据门/候选，不得绕过 session 与权限过滤。

## 4. 排序

对候选并集分别归一化：

- `lexicalNorm = bigramScore / maxBigramScore`（查询内归一化）；
- `semanticNorm = (cosine - min) / (max - min)`（候选内 min-max）。

融合分数：

```text
0.25 × lexicalNorm + 0.75 × semanticNorm + exactIdentifierBoost
```

`exactIdentifierBoost` 只给硬标识符精确命中，值为 1。排序并列时按记录时间降序，再按 id 升序；最终按前 80 字去重并截断到 5 条。

语义权重较高，是为了让“换说法”在词面覆盖率低时仍能排到前面；bigram 权重用于保持同义候选中的精确词面优势。该权重在 dev set 上冻结，保留集只回测一次。

## 5. 为什么不做全局阈值

P3-1 已证明全局阈值会把正例一起删掉。P3-2 的弃权是**证据存在性**问题，不是连续分数问题：

- 没有词面证据 → 不回答；
- 有证据但被拆散在多个事实中 → 不回答；
- 有硬标识符 → 强证据；
- 有完整词面证据 → 允许语义排序决定顺序。

这使负例正确率不依赖模型分数的绝对刻度，也避免模型升级后阈值漂移。

## 6. 已知限制

- 别名覆盖不足时，完全换说法且无词面锚点的查询会被误弃权；这是保守方向的错误。
- `split-evidence` 会拒绝需要跨两条记录拼合的多跳问题；当前单事实回忆场景接受该限制。
- min-max 归一化对候选集大小和异常低分敏感；生产化需要用真实分片规模复测。
- 仍是 Ollama 边车方案：进程模型、安装体积和故障降级没有因本设计而解决。
- 评测语料是合成、小规模、单用户，不代表千级真实消息上的别名漂移和长尾查询。

## 7. 结论

Hybrid 是当前证据下最合理的 P3 质量候选：它保住了 embedding 的改写召回，又把弃权从不可靠的全局阈值改为可解释的词面证据门。它**不是生产验收**；生产接入仍需单独决定边车/进程内后端、别名治理、故障降级与真实规模复测。
